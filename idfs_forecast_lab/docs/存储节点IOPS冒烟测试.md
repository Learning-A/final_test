# 存储节点IOPS冒烟测试

用户最新要求：预测目标改为每个存储物理节点，聚合对应12个OSS；先执行一轮冒烟，将采集、预处理、GPU训练、CPU在线预测和日志复算串起来。此前35轮计划标为deferred，不在本轮执行。

## 口径与对象

节点读IOPS为所属12 OSS的读次数差分之和，写IOPS同理，总IOPS为读加写。100ms桶保存次数和实际间隔，完整1秒窗口由10个有效桶计数相加。节点任一成员OSS缺失或无效，该窗口无效，不补零。8节点总和在全部成员完整时等于96 OSS集群总量。客户端NFS计数作为辅助特征，不混入节点实际IOPS。

| 节点 | OSS |
|---|---|
| idfs44 | 0—11 |
| idfs45 | 12—23 |
| idfs46 | 24—35 |
| idfs47 | 36—47 |
| idfs64 | 48—59 |
| idfs65 | 60—71 |
| idfs66 | 72—83 |
| idfs67 | 84—95 |

配置中`formal_targets`登记八个节点，旧单值`formal_target`仅保留idfs44作为兼容默认值，不能解释成只预测一个节点。

## 本次实际流程

1. 使用现场背景I/O，短时只读采样120秒，96 OSS和16客户端同时采。没有启动额外压测、修改数据文件、清缓存或停止既有工作。
2. 原始数据保存在`runs/host_smoke_20261121_capture`，处理结果在对应`_processed`目录；累计计数、质量标记、来源哈希均保留。
3. 同次采集按时间顺序划分训练与验证段，中间留10秒间隔，避免五秒历史跨入训练标签段。各节点取得66—72个训练样本和25个验证样本。它们不是独立运行的实验轮次，不用于正式验收。
4. 在`lmj@b507`新任务目录，对八个节点各训练一个真实三路MoE，12个epoch，仅选择当时空闲的一张A40，最多4 CPU线程、0 DataLoader worker。原有环境、缓存及其他工作的PID未修改。
5. 导出只含推理代码的CPU包，进行GPU/CPU对拍。idfs67初次导出未通过严格等价检查，保留失败记录；后续统一采用float64推理，训练仍为float32，等价门限维持1e-5。当前v3八个模型均按这一方式导出，早期float32包保留为历史证据。
6. client7414无既有PyTorch/Pip，本次将校验过的Linux CPU wheels安装到`/home/hust/idfs_forecast_inference/runtime/host_smoke_20261121`。专用解释器设置私有模块路径，不安装到系统或既有用户环境。PyTorch为2.4.1+cpu，NumPy为1.24.4。
7. 在client7414的专属发布目录核验CPU运行结果。首个八服务重复转发的尝试出现带宽积压，已结束本次自己的控制进程，并确认八个远端服务全部结束，保留失败证据。改用单个CPU服务、共享计数状态和八个模型；SSH压缩只作用于本次连接。模型在READY前预热，stdin EOF后自然结束。
8. 下载预测、提交回执、节点/OSS实际窗口、原始计数和校准日志，核对哈希，独立复算节点聚合、发布时间、预测与实际配对和零值排除数量。

在线阶段使用明确标记的“背景观测起点”，不伪造负载首I/O。`observation_start.json`与正式`first_io.json`分开，协议标为`smoke_not_acceptance`。正式冻结入口拒绝同次采集时间切分得到的冒烟模型。

## 模型与验收限制

每个模型的时序输入已改为该节点历史IOPS，空间输入为96 OSS同物理节点图，跨层输入包含节点和客户端观测。三路专家为GRU、GCN和MLP，通过可学习门控融合。推理输出读、写、总量和三路权重，EWMA校准仅使用已经结算的历史残差。

本轮小样本、12 epoch用于检验工程链路，不能证明模型准确率达标，也不能代表五类正式负载。准确率仍只排除实际零值；低正值背景IOPS会放大MAPE，复算结果应如实保留负值等结果。局域网时钟精度未通过正式核验，当前不作正式准确率或三轮通过声明。

实际结果以`runs/host_smoke_20261121/smoke_report.json`及同目录训练、部署、实时采集日志为准。功能检查和正式验收分别记录。

第二次现场记录在`live_v2`，因逐条转发导致特征到达不及时，每节点仅7个有效预测配对，未通过至少10个配对的冒烟检查。v3使用50ms/最多128条的批量转发，记录在`live_v3`。归一化显式使用log空间标准差下限0.25，避免小样本常量维度放大后续普通变化；原始计数不裁剪、不修改。

八个模型顺序执行的冒烟发布余量为200ms，预测仍须在目标窗口开始前算完并落盘；这不是对正式协议30ms发布余量的性能验证。原始累计计数由共享采集器保存在`live_v3/raw`，推理端原始副本保留在远端新任务目录；下载共享窗口和各节点日志进行复算，避免重复传输八份原始记录。

Windows时钟与集群时钟存在约16秒差值，因此不能直接把Windows接收时间减源采样时间当作网络延迟。本轮观测锚点、特征可用时间和预测发布均使用集群推理主机时钟；正式时钟精度仍未核验。

## 脚本入口

`python -m idfs_lab.smoke`提供prepare、runtime、train、stage、live、recompute六个阶段。它们是有实际效果的冒烟执行入口，输出使用新目录，不覆盖已有实验；不应重复运行已完成阶段来覆盖证据。GPU任务与发布包使用唯一标识。

八模型实时共享流入口为`python -m idfs_lab.smoke_multi`。旧`smoke live`保留作首个失败尝试的源码记录，不再作为推荐入口。
