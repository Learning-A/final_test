# 集群下一秒IOPS：数据、指标与90分可达性复审

2026-11-23，北京时间。用户明确优先“存储集群总IOPS，下一完整1秒”。本次只重算原冻结预测和研究指标依据：没有重训、改变checkpoint、平滑目标、使用外部validation或恢复心跳。原正式定义未被本报告自动替换。

## 1. 结论

集群总量直接预测以前已经做过，并非从未尝试。R1的独立集群森林头在当前2661个train03秒上，五负载等权WAPE为19.1446%；按100×(1−WAPE)展示为80.8554分。相同R1节点求和是80.6109分。现有候选中，R2 L2节点求和的WAPE较好，为17.9677%，对应82.0323分。所有已审候选、所有五负载的WAPE均未小于10%，没有可据此宣称90分的模型。

另一方面，MdAPE是有文献与成熟实现的指标。对同一R2 L2集群求和预测，五负载等权MdAPE为9.6399%，若明确展示为100−MdAPE，得到90.3601分。它评估典型/中位相对误差，并不表示90%秒的预测落在10%误差内，且逐负载仅2/5满足MdAPE<10%。这可以作为新的业务口径候选，不能直接变成原指标达标或正式独立验收证据。

**推荐面向整体负荷与资源规划，以集群1秒WAPE准确度作为主指标、保留90分目标，同时报告典型误差与容差命中率。当前还需要真实模型改进。若业务确实只考核典型负荷，可将MdAPE另定义为典型预测精度，但应明确其有限含义并前瞻验证。**

## 2. 原结论需怎样理解

原节点MAPE约94%–115%与目标<10%相比，确实约差一个数量级。但这不能推出所有有意义的预测误差也相差十倍：MAE/WAPE/典型相对误差表达不同业务损失，现有集群WAPE约18%–19%，距10%的差距约为1.8–1.9倍。

44.0585是原R2 L0中实际值>10 IOPS各档对**原40组宏MAPE**的贡献百分点。它保持原全体正值分母，所以不是删除1–10档后重新归一化的条件MAPE。它描述一个已训练模型的冻结残差，不是数据或模型族的不可约误差下界。普通窗口确有问题，但尚无数学证据证明任何因果模型都不可能低于10%。

已知证据包括：少数真实低值对MAPE影响大、部分下降晚于假设截止、现有探针误报多、四轮均值相近但AI/Graph逐秒曲线弱重复。它们支持需要重新审视信息与目标，不支持断言全部剩余误差都来自噪声或不可预测系统停顿。

## 5. 可替换的指标与90分究竟表示什么

### A. WAPE准确度：整体负荷量的首选

WAPE=sum_t(abs(pred_t−y_t))/sum_t(y_t)，候选展示分数A_W=100×(1−WAPE)。所有完整秒的绝对误差都计入，实际零的预测误差也进入分子。分母是该负载的总真实量，而非逐个很小y_t，所以避免少数近零点获得无限大的逐点权重。

业务含义是“总绝对预测误差占真实操作总量的比例”。它适合负荷量、资源规划；不等于每秒误差都很小，也不能替代低状态预警。Amazon Forecast正式使用WAPE，已有旧工程acc_wape也采用1−WAPE。补成百分制分数是这里显式定义的展示方式，不称其为所有文献统一的准确率公式。

90分要求WAPE<10%。当前较好候选为82.03分，要到90，绝对误差总量还需降低约44.34%，不能靠改名取得。五负载等权、每负载各自和最差负载同时报告；不把Graph的大量IOPS混入一个总体分母后遮盖其它负载。

### B. MdAPE典型预测精度：有依据且当前宏分数可以超过90

MdAPE=median_t(abs(pred_t−y_t)/y_t)，候选A_M=100×(1−MdAPE)。标准MdAPE的定义和实现见sktime，引用Hyndman与Koehler的准确度度量研究。当前集群样本实际零数为0，因此本次中位数计算没有排除零带来的范围差异；以后若出现零必须先固定零规则。

R2 L2结果：

| 负载 | MdAPE% | 典型精度A_M | ±20%容差命中率 |
| --- | ---: | ---: | ---: |
| AI训练 | 10.4866 | 89.5134 | 67.39% |
| AI推理 | 11.3661 | 88.6339 | 69.29% |
| Baleen | 10.8755 | 89.1245 | 76.70% |
| Graph | 6.3982 | 93.6018 | 78.49% |
| WRF | 9.0732 | 90.9268 | 72.67% |
| 五负载等权 | 9.6399 | 90.3601 | 72.91% |

这里“90.36”是五个负载各自中位误差的等权补分，不能解释为90.36%的秒准确；逐负载只有2/5超过90。把全部2661秒混合后再取中位数，会得到另一数90.6381，不能与等权口径混写。MdAPE对极端误差稳健，但尾部坏到多严重也可能不改变中位数，因此不建议作为资源风险任务唯一验收。

如果项目确实重视典型运行水平，它可列为“集群下一秒典型负荷预测精度”候选，并保留WAPE、Q90误差和突降误报/漏报。当前90.36仍来自已经用于开发的数据，正式验收不能由本次补算直接替代。

### C. 容差命中率：最直观的“90%的秒预测正确”

Hit(tau)=100×mean(abs(pred−y)<=tau*y)。例如tau=.2表示在±20%以内才命中，目标Hit>90%明确表示至少九成秒落入业务容差。若需要绝对容差a，则预先定义abs(error)<=max(a,tau*y)，a必须来自业务可接受的IOPS误差，不能看结果反推。

当前R1直接集群头的宏Hit(20%)为74.56%，R2 L2求和为72.91%，未达90%。R1直接头要覆盖90%正样本，各负载经验容差约需±55.59%到±87.49%，这些只是描述分位数，不是建议的新验收容差。10/50/100IOPS绝对容差敏感性没有改变本批Hit(20%)结果，当前不足不只是几个接近零的点。

### D. 其它有依据的误差指标

| 指标 | 意义与出处 | 能否自然代表90%准确率 |
| --- | --- | --- |
| R² | 组内方差解释程度，标准回归实现；每负载独立计算 | R²=.9是解释90%方差，不是90%秒准确。当前逐负载远未到.9，不能混负载均值制造高R² |
| sMAPE | 用真实与预测之和归一，成熟预测库有实现 | 必须固定0–200%或0–100%约定；两种数值差一倍，不能在看到结果后换约定。不是当前MAPE<10%的等价替代 |
| MAAPE | Kim与Kim提出对APE取atan，缓解间歇需求中的极端比例误差 | 单位是弧度，不能直接叫90%准确率；额外归一补分需解释角度误差对应的业务含义 |
| MASE | 相对训练期朴素基线的尺度误差，Hyndman与Koehler | <1表示胜过基线，没有天然90%含义；本轮未在本机拟合其训练尺度 |
| logMAE/RMSLE、log准确比 | 描述倍数误差，Tofallis讨论log准确比 | 适合作辅助量级误差。对log值再算MAPE并补100会受reference和单位定义影响，不能直接当原IOPS准确率 |
| 固定容量归一MAE/RMSE | 将误差表达为已测定服务容量的比例，适用于利用率/容量控制任务 | 只有独立、有业务定义且同工作负载下的容量C才合理；当前未有合格C。A_N=1−MAE/C到90需C>10MAE，不能拿测试最大值或任意大C当容量 |
| 90%预测区间覆盖率 | 不确定性覆盖概率 | 宽区间也能高覆盖，必须同时约束宽度和业务风险；不是90%点预测准确率 |

原历史审计曾记录0.1秒arrival/concurrency任务acc_wape约93.29%和91.51%，说明1−WAPE在不同目标和数据上确有超过90的先例，但不能把其成绩移到当前1秒OSS集群目标。旧R²高分同样不能替代本任务证据。

## 6. 可执行的下一研究方向

先将研发对象明确为集群下一完整1秒，节点结果作为解释与诊断保留；是否改变正式验收对象/公式应写入新协议。本报告按用户优先级完成分析，没有修改既有正式配置。

若业务以整体负荷规划为主，建议固定WAPE补分>90为主目标，逐负载报告并约束最差负载，同时报告MdAPE和Hit(20%)。下一张真正有区别的卡应复用现有R1独立集群头作为冻结基线，单独训练集群目标，用集群MAE（对固定评估分母与WAPE一致）优化、按集群WAPE选择checkpoint，训练期负载平衡先登记。它不同于重跑按节点MAPE选模的R2/V2；不同时改输入、骨干、指标和采样周期。当前尚未执行该新卡，也不承诺它能降低44%的误差。

若项目接受“典型预测精度”，可保留90的数值要求并明确采用A_M，但须同时注明这是中位误差口径、当前五负载中仅2个单独通过、总体WAPE约18%，且新定义要前瞻验证。若硬性要求是每类负载的九成秒均在±10%/20%以内，则当前证据不支持达标，不能用MdAPE补分代替。

若在新集群目标下仍不足，优先补齐原生阶段的真实可用时钟、请求到完成的已到达先兆、采样曝光和服务接收证据，再判断是否需要更多完整训练轮。GC、缓存或调度等原因仍需证据；不能继续靠无界堆模型或换分母解释所有残差。
