## 交互与任务状态

总协调入口是 [Issue #17](https://github.com/Learning-A/final_test/issues/17)，本阶段独立任务各有一个 owner。A/B分别维护自己任务正文中的状态；涉及对方的变化通过评论提出请求，不覆盖对方记录。更新由两端下一次实际运行时读取，不会直接唤醒另一台电脑。

每次开工阅读协调入口、自己的任务、对方未解决请求与相关 PR。现有任务 running/completed 时检查产物和状态，避免重复运行。任务结束至少写出代码 SHA、数据 SHA、命令/配置、结果、证据路径、限制、下一步和对方需要的动作。

统一状态为 queued → accepted → running → delivered → verified/needs_fix。blocked 时写具体缺项与请求对象，缺项之外的工作继续做。delivered 表示对方可下载且哈希已校验，verified 表示接收方复核过，不提前把交付写成验证通过。

请求模板：

> request_id / owner / 优先级 / 需要解决的问题 / run与窗口范围 / 已有证据 / 期望产物和schema / 依赖 / 状态

交付模板：

> request_id / 代码与数据SHA / 下载或报告链接 / 实际完成与检查 / 未解决项 / 接收方下一步

A 使用 experiment/ 分支，B 使用 model/ 分支。变更走独立 PR；小报告入 Git，大数据与权重走 Release。保留本地未提交工作，禁止强推。A 维护数据清单和现场证据，B 维护模型实验卡和结果；共享文档的小改动通过 PR 合并。
