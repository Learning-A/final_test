## 比较范围

每轮只取 recording_start 后0–600秒内的完整整数秒，八节点各12 OSS均完整才入比较；不补零，不平移时间轴寻找最高相关性。因起点非整秒且有缺失，各轮有582–594个共同节点完整秒。

这个范围与D0的整段660秒录制不同，也与模型5,328/2,661共同键不同。**recording_start不是原生RD或preIO的已认证起点**，本表可能含启动等待，并未声称各业务阶段精确对齐。无法用本表相关性证明随机过程没有可预测性，也不能证明GC/调度/缓存是停顿原因。

## 原生仓库与实际运行的核对

原生版本：[ChrisLzt/idfs-workloads@fb83711a1226f59899ed034b9195402156ef57d6](https://github.com/ChrisLzt/idfs-workloads/tree/fb83711a1226f59899ed034b9195402156ef57d6)。本次重新读取五类README/model和四个Java适配器；Baleen README请求超时，使用其已取得的model、Java与此前核对的说明，不伪称本次成功获取该README。

**20/20实际运行model SHA与固定上游model.json完全匹配。** 每类四轮的run_current配置、layout、data_root和记录的asset SHA集合均一致。这里layout相同表示文件/逻辑布局清单相同，不证明逐轮物理放置、缓存、后台服务、CPU调度和时钟状态相同。

| 负载 | 原生机制 | 与本次四轮现象的关系 |
| --- | --- | --- |
| AI训练SES | 单600秒阶段，70/30读写，类别内Zipf、逐IO独立重选，iorate=max，不设逐秒配额，不在秒边界重置随机流 | 稳定混合分布有助于解释均值/完成读写占比稳定；实际请求完成数及瞬停时刻没有被配置锁定。没有业务epoch/checkpoint阶段可直接预测。 |
| AI推理SES | 单600秒阶段，80/20读写、64/128KiB混合，类别内独立随机流和偏移，max-rate | 整体量级稳定但逐秒曲线弱相关符合“相同请求分布、不同完成时间”的可能机制。它不是实际模型prefill/decode跟踪。 |
| Baleen | 时间相关联合请求分布，按preIO实际经过时间选择对应分布；Vdbench负责发压和结束，没有逐秒完成配额 | 粗粒度趋势存在重复，但同秒完成量不会等于原访问频次。需核对原生时钟起点和完成滞后才能启用已知计划。 |
| Graph | 32B随机纯读、固定全局Zipf热点和各通道独立随机流，单600秒、O_DIRECT/max-rate，无逐秒请求配额 | 空间份额稳定且时间波形弱相关；Zipf是空间偏好，不能当时间周期。源代码未给出三个固定“业务停顿秒”。 |
| WRF | 0–60/60–150/150–510/510–600秒四业务阶段，读写文件角色切换、阶段内Zipf，max-rate | 10秒趋势相关0.77–0.91与阶段结构一致，值得单独研究。Java时钟从首次使用单调时钟开始，与recording_start不能直接等同，需已有日志对齐。 |

AI适配器在generate中持续scheduleIO，由preIO按运行时钟调用timeline.next并决定offset/size/readFlag。Baleen类似，源码注释明确队列生成时不决定源频次或实际读写方向。WRF使用System.nanoTime的相对经过时间；Graph由Vdbench RD管理时间和速率、回调选择地址。**相同随机种子或模型哈希不保证第N秒完成相同数量的IO**，即便请求顺序可重复，请求进入和完成时间仍受运行系统影响。

OSS完成读比例与应用请求比也不同：本范围AI训练约47.94%–47.98%，AI推理约62.98%–63.00%，Graph约99.99%。它们与原70%/80%应用读取请求比不能直接相减判错，更不能据固定副本/EC系数硬改标签；观测层、拆分/合并及服务行为必须区分，具体机制仍待证据。

## 这对后续研究意味着什么

1. “每类四轮是同样的负载配置”已有实物证据；“每秒目标可按时间复刻”缺少支持。AI/Graph不应把某轮低值秒记成固定时间模板。
2. WRF应优先做原生阶段起点核验、分阶段读写与份额比较，Baleen应核验原生时间分布与完成滞后；当前记录偏移相关性仅提示路线，不能直接做在线阶段输入。
3. 新模型若再比较跨轮稳定性，应冻结输入/选择规则，按完整轮留出并逐负载/节点报告，不能随机拆秒。V2无晋级候选而跳过G1是停止规则，不代表完整跨轮比较已做。
4. 本次没有恢复已结束心跳或发起训练/采集。先完成数据层结论，任何新增模型研究需明确新问题和预算，避免重跑V2失败卡。
