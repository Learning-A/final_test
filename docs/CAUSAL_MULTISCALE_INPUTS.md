# 因果多尺度/读写/空间输入准备 v1

新模块multiscale_inputs.build_input只处理一个采集包内的历史，不拟合、不训练、不读取未来标签。它输出host_multiscale_causal_v1：默认97个具名输入，分为15维read/write/total五历史、50维5/15/60秒分布统计与差分/读比例/零值标记、32维八节点最近读写总量及观测mask。上下文节点不含客户端计数，不宣称请求归属。

输入index使用joint.index_windows按scope/entity/秒索引，重复窗口拒绝。必须按完整采集身份逐包构造index，capture_id由dataset/batch/attempt/manifest确定，不跨run拼接。时间start是要预测的未来一秒起点，最新可用历史从start-2秒开始、结束在start-1秒；所有被消费窗口的available_epoch_ns必须<=start-30ms。不完整/迟到的本节点必要历史直接拒绝，邻居观测缺失仅在输入张量用0占位且mask=0，实际零观测mask=1；不产生或补写标签。

多尺度统计只描述已经可用历史，不是从训练/验证数据拟合的归一化。差分可能为负，不能沿用旧联合输入读入器的“所有元素非负”假设。后续模型适配需按feature_names、feature_groups、scales、host_order和schema冻结维度及顺序；不能拿新97维输入直接调用旧415/6维权重。scales可以预先固定(5,)或(5,15)；非默认scale方案须连同完整元数据记录，不能只以schema名称判断权重兼容。

## 覆盖率实测，不是模型成绩

在已校验的两份新train候选包上，仍使用recording_start+[0,600)秒暂定区间和相同完整标签。默认要求本节点连续60秒完整且及时历史，共同八节点有效秒由五历史基线的562/546降至302/218（AI训练/AI推理）。这说明长上下文携带额外信息的同时显著牺牲可用性；不应仅在更容易的交集上报告模型提升。

AI训练按节点可用秒：540、477、418、418、540、540、494、540；AI推理：413、541、540、540、479、357、539、479，顺序idfs44/45/46/47/64/65/66/67。这些计数来自每个完整目标标签调用build_input后是否非None，无模型拟合。

下一步预先比较5/15/60秒配置的覆盖和信息收益，公平消融同时给出共同样本性能与各自总覆盖。可另设计长历史缺失mask/统计覆盖率方案，但需新schema、测试和明确缺失统计语义，不能静默填零或改标签。100ms桶/辅助指标仍等A审计已有数据后再引入。

完整五类的首次端到端试运行尚未触发：目前仅AI训练/推理候选有可核验包且时间边界仍待复核；Baleen/graph/HPC尚无已交接有效轮证据。唯一测试ID all-workloads-first-round-e2e-v1，等各类至少一轮有效采集后只执行一次，不等满20轮，不提前以旧故障数据代替。

功能验证覆盖：已知统计与特征顺序、未来/目标标签不影响输入、缺历史拒绝、到达deadline边界、邻居缺失与实际零区分、重复窗口及坏值拒绝。本次没有GPU训练或现场操作，候选质量和正式协议均未改。
