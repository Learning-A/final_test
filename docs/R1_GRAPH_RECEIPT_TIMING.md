# Graph 三轮的采集端接收时间

检查 Graph 的三个原训练轮。按每条 OSS 原始记录的 `scheduled_epoch_ns` 分组，只统计 96 个 OSS 都有有效源样本和接收时间的组。在同一个 Windows 采集进程的单调时钟上，用该组最后一条记录的 `received_local_mono_ns` 减去第一条的值。此差值描述本次记录的组内到齐跨度，受采样调度、传输、采集处理和源端时钟差异共同影响。

| 轮次 | 完整组数 | 到齐跨度中位数 | P95 | 最大值 |
| --- | ---: | ---: | ---: | ---: |
| train01 | 6,600 | 48.6 ms | 157.0 ms | 606.9 ms |
| train02 | 6,591 | 52.7 ms | 179.7 ms | 587.3 ms |
| train03 | 6,589 | 49.2 ms | 151.0 ms | 640.6 ms |

有效原始记录全部具有源端和接收端时间戳，三轮均未发现采样器记录的 `clock_step` 标记。逐主机计算 Windows 接收墙钟减源端读取结束墙钟，各轮主机中位数约为 16.82、16.87 和 16.91 秒。该差值包含跨机时钟偏差与链路耗时。当前归档仍不能给出逐轮时钟误差上界或线上推理端接收时间。

本报告可辅助解释 [R1 离线覆盖审计](R1_TIMING_COVERAGE.md) 中的假设余量。完整结果在 `reports/r1_graph_receipt_timing.json`。正式发布余量仍需在目标部署环境中测量。
